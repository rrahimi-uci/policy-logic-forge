\section{LEXEC: a bounded compiler instrument}

\subsection{Provenance-preserving pipeline}

The system ingests documents, preserves byte- and chunk-level identities,
extracts candidate rules, normalizes them into a versioned contract, compiles
supported constructs to \lexir{}, validates references and decision tables,
and emits executable artifacts. Every stage records input and output hashes,
configuration, model identity, timing, retry history, and terminal state. A
reviewer can therefore traverse from a run to a rule, its source span, and its
validation or execution trace without reconstructing an implicit chain.

\subsection{Typed IR and fail-closed lowering}

\lexir{} v1 represents typed values, predicates, decisions, tables, references,
exceptions, and source anchors. The validator checks type compatibility,
reference resolution, hit-policy obligations, bounded overlap and coverage
properties, and selected counterexamples. Unsupported temporal, quantified,
external-context, or unbounded constructs produce a stable refusal with source
provenance and a remediation hint. A refusal is not a negative answer to the
normative question; it states that this compiler version will not manufacture
an interpretation.

This boundary matters because syntactic validity and semantic fidelity are
different failure modes. Autoformalization can improve or degrade downstream
reasoning depending on task and representation \citep{ganguly2025grammars}, and
an LLM can report a solver-like conclusion without faithfully executing the
formal program \citep{wang2026limits}. In \lexec{}, compiler and solver paths
are deterministic and make no model calls; model-produced extraction remains
upstream and independently auditable.

\subsection{Execution and proof records}

The runtime evaluates a bounded FEEL/reference subset with explicit null and
error semantics. The emitter serializes the same IR to DMN 1.3, whose standard
defines decision tables and FEEL \citep{omg2021dmn}. Bounded solver queries
produce machine-readable witnesses for satisfiability, overlap, coverage, and
selected conflicts. These are diagnostic properties of the encoding. They do
not prove that the encoding is true to the source. Cross-engine agreement is
therefore a separate OE gate.

\subsection{Immutable review overlay}

The review workbench consumes versioned run manifests and evidence packets
through a read model rather than importing pipeline internals. It exposes stage
status, rule and refusal queues, source/artifact comparison, graph navigation,
search, annotations, and run comparison. A review decision stores author,
timestamp, target hash, and disposition without mutating the compiled artifact.
If the target changes, the decision becomes stale by construction.
